How the Layered Security Curriculum Dashboard Works

A plain-language walkthrough of Layered_Security_Certification_Dashboard.html — what data it holds, how each section is calculated, and how the pieces talk to each other.

In one sentence: it's a single, self-contained HTML file with the entire learner roster baked in as JSON, which JavaScript filters, aggregates, and renders into cards, charts, and a roster the moment the page loads — no server, database, or login required.

01 What data is inside it

The file embeds one JavaScript array called PEOPLE — 33 learners assigned to the Layered Security Certification – Direct Sales curriculum, built from the LMS export you provided. Solutions Consultants and anyone in the Commercial Print market were deliberately excluded per your instructions.

Each person is one JSON object with:

FieldWhat it holds
FirstName / LastName / EmailIdentity
JobTitle / Market / Manager / MgrEmailOrg placement, used for grouping and filtering
HireDate / AssignDate / DaysRemainingTimeline fields; negative DaysRemaining plus not-yet-complete drives the "Past Due" flag
Complete (Yes/No)Whether all 11 curriculum modules are finished
CompleteDate / CompleteQtrDate of the last module finished, and its fiscal quarter
ls.items[]The 11 individual modules, each with done (true/false) and a completion date
overallDone / overallPctModules finished out of 11, and that as a percentage

Nothing is fetched from a server — this array is the entire dataset, sitting in a <script> tag near the bottom of the file.

02 The three-tier status model

Every calculation in the dashboard boils down to one of three curriculum states, computed by a single function (personStatus) that everything else reuses:

Not Started→ In Progress→ Complete

This is deliberately kept separate from an entirely different concept — actual certification, which your organization only grants once someone has also hit $5,000 in qualifying sales, tracked in an external system this file has no access to. The dashboard never conflates the two: finishing all 11 modules only ever shows as "Complete," never "Certified."

03 Section-by-section

Header

Title, current data date, an Import Sales Certification button (see §5), the Export menu (see §6), and a light/dark theme toggle that's remembered in the browser via localStorage.

Filter bar

Two dropdowns (Status, Market) and a search box. Changing any of them re-runs one function, applyFilters(), which rebuilds a filtered array from PEOPLE and then re-renders every stat, chart, and roster row from that filtered set — so the whole page always reflects the current filter combination.

Stat cards

Total Enrolled
Count of everyone in the current filter
Curriculum Complete
Count where Complete === "Yes"
Certified
Count confirmed by an imported sales file — reads "—" until one is loaded
In Progress / Not Started
Split by whether any modules are done yet
Past Due
Not complete and DaysRemaining < 0
Completion Rate
Complete ÷ Total, as a percentage

Charts

Both are drawn with Chart.js (loaded from a CDN):

  • Completion Pipeline — one horizontal bar per status (Not Started / In Progress / Complete), so you can see the shape of the funnel at a glance.
  • Learners by Market — a stacked horizontal bar per sales market, so you can spot which markets are lagging.

Both charts destroy and redraw themselves every time filters change, so they always match the roster below them.

Roster

A two-pane layout: a scrollable list of people on the left, and a detail panel on the right.

  • Individual view — sortable by Name, Status, or Completion %.
  • By Manager view — the same people, grouped into collapsible sections under their manager, with a per-team completion count in the group header.
  • Each card is color-striped (green/yellow/red) by status, and shows small pills for module progress, a Past Due flag when relevant, and a Certified Layered Security Specialist pill once that person is confirmed via an imported sales file.
  • Clicking a card opens the full detail panel: contact info, manager, hire/assign dates, days remaining, a certification badge, and an expandable checklist of all 11 modules with their individual completion dates.

04 Where the numbers come from — a worked example

Say you filter Status to "In Progress" and Market to "Heartland Sls." Here's the chain of events:

applyFilters() reads both dropdowns→ PEOPLE.filter(...)→ renderStats() recounts the 6 cards→ renderCharts() redraws both charts→ renderRoster() rebuilds the left-hand list

Nothing is precomputed — every one of those steps runs fresh, in order, on every filter change, directly against the in-memory PEOPLE array.

05 The Certified/sales-import mechanism

Because real certification depends on sales data this file doesn't have, the dashboard includes a way to bring that data in yourself, entirely in-browser:

  1. Click Import Sales Certification and choose a .csv or .xlsx file.
  2. The file is read with SheetJS (also loaded from a CDN) and converted to rows of key/value pairs.
  3. The code looks for a column whose name contains "email" (case-insensitive) to match people, an optional column containing "certif" (Yes/No, True/False, 1/0) to decide who's certified, and an optional column containing "date" to show alongside the badge.
  4. If there's no certification column at all, everyone whose email appears in the file is simply treated as certified.
  5. The result is saved to localStorage under the key ls-sales-cert, so it survives a page reload — but it lives only in that one browser, not shared with anyone else who opens the file.

Worth knowing: because the import is local to each browser, this only works as a "confirm once, see everywhere" solution if everyone imports the same file themselves, or if the data is baked directly into the file for you ahead of time.

06 Exporting

The Export menu offers three report types, each available as a browser print (formatted for a printer-friendly PDF) or a downloaded Excel workbook, and each respects whatever filters are currently applied:

  • Full Report — everyone currently shown, with module completion %, status, and manager.
  • Not Complete — a contact list of people still working through the curriculum, sorted by manager, meant for follow-up.
  • Manager Summary — one row per manager, with team size and completion counts, sorted best-to-worst.

07 Technical notes

  • Single HTML file — CSS, data, and JavaScript are all inline. No build step, no server, works by double-clicking it or opening it in any modern browser.
  • Two external libraries are pulled from a CDN at load time: Chart.js (charts) and SheetJS/xlsx (reading imports and writing Excel exports). An internet connection is needed the first time those load.
  • All state (theme choice, imported certification data) lives in the browser's localStorage — clearing browser data resets it.
