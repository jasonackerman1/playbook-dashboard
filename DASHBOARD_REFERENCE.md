# Playbook Dashboard Suite — Reference Documentation

Last updated: 2026-09-28

This is the **master reference** for every dashboard in this repo — what each one is for, what
it measures, and the custom formulas/business rules baked into it. It is a *reference*, not a
changelog: it describes what each dashboard IS today, not the history of how it got there. For
recent changes and what's currently in flight, see `PROJECT_STATUS.md`. For deep build history,
gotchas, and lessons learned, see Claude's project memory (`cert_dashboard_plan.md`,
`lms_engagement_dashboard.md`, etc.).

**Maintenance:** this file is updated every time Jason says "save everything," alongside project
memory, `PROJECT_STATUS.md`, and the global CLAUDE.md — folding in whatever changed to a
dashboard's purpose, metrics, or formulas during that session. See the global CLAUDE.md's
"Checkpointing Work" section.

An older single-dashboard explainer, `Dashboard_Documentation.html` (Layered Security only,
styled as a standalone dark-theme page, bundled into that dashboard's original 2026-07-29 build
commit), was retired and deleted 2026-09-28 once this file superseded it — this markdown file is
the sole source of truth going forward.

## Shared conventions (apply across every dashboard unless noted)

- **Architecture:** each dashboard is generated by a Python script (some now shell out to Node —
  see LMS Engagement) that reads source data and writes a single self-contained static HTML file.
  **Never edit a generated `.html` file directly** — always edit the script and regenerate, or the
  next data-driven regeneration will silently overwrite the edit.
- **Hosting/update loop:** data files (Excel exports, mostly from Resmie Biba) get dropped in a
  dashboard's data folder and pushed to `main`. A GitHub Actions workflow detects the change, runs
  the script, and auto-commits the regenerated HTML — then a second job deploys the whole repo to
  GitHub Pages. Never commit generated HTML by hand; let Actions do it (see `PROJECT_STATUS.md` for
  the recurring "Actions-vs-Actions push race" gotcha this causes).
- **Navigation:** every dashboard's `<h1>` triple-clicks back to `index.html` (the homepage). Some
  dashboards also have a bi-directional hamburger (☰) menu linking directly to a few sibling
  dashboards — not universal, check the individual dashboard's section below.
- **Theme:** shared `pb-theme` localStorage key drives a light/dark toggle on every dashboard.
- **KM fiscal year/quarter:** April–March, named by the starting year (e.g. FY2025 = April 2025 –
  March 2026). Quarters: Q1 = Apr–Jun, Q2 = Jul–Sep, Q3 = Oct–Dec, Q4 = Jan–Mar. Always computed in
  Python/JS from the actual date — never trust a quarter label baked into a source LMS export (one
  was found to be off-by-one).
- **TLG (leadership/admin team):** Jason Ackerman, Bianca Davis, James Parker, Resmie Biba, Chris
  Curtis, Sara Thompson, Jeremy MacBean, Bradley Pierce, Laura Sefcik, Samantha Maresca, Staci
  Musco, CJ Homer, Rich Moore, Dale Kinsey, John Lechner, Resmie Nesimi, Samantha D'Angelo, Bianca
  DiPasquale, Doug Falk. Most dashboards exclude this list from stats by default, either as a
  toggle-able "Hide/Show TLG" button or a permanent, non-toggleable exclusion — which applies to
  which dashboard is noted below, since it varies and two dashboards (LinkedIn Learning Engagement,
  LMS Engagement) genuinely can't apply it at all because their data has no name field.
- **"Data through [date]"**: every dashboard states, near its title, the actual date its
  underlying data covers — never today's date, and never a hardcoded string (always derived from
  the source filename or the data's own max date, so it updates itself on every regeneration).

## 1. Analytics Hub — Homepage

**File / Script:** `index.html` / `generate_homepage.py`

**Purpose:** the front door. One card per dashboard, each showing a live headline stat pulled
directly from that dashboard's own data (by importing that dashboard's own loader/stats function —
there is no separate homepage data source, so the homepage can never show a number that disagrees
with the dashboard it links to).

**What it measures:** nothing of its own — it's a summary aggregator. Each card shows 2-4 of that
dashboard's own key numbers plus its "Data through" date.

**Custom formulas:** none. Purely cosmetic: a particle-network background, an aurora header glow,
and animated count-up stat numbers.

**Hidden nav:** triple-clicking the "Analytical Data Hub" title goes to the hidden Internal
Dashboard Traffic dashboard (#3) instead of doing nothing, the reverse of every other dashboard's
triple-click-home pattern.

## 2. Playbook Traffic

**File / Script:** `playbook.html` / `update_dashboard.py`

**Purpose:** tracks visits to the actual **sales playbooks** (Accelerate, Healthcare, Public
Sector, Legal, etc.) — external content usage by the sales org, not usage of these internal
analytics tools (that's Internal Dashboard Traffic, a separate dashboard).

**Data source:** weekly (formerly monthly) Excel exports, one row per page view — visitor, URL,
date, region. Cadence changed from monthly to weekly 2026-08-13.

**What it measures:** Total Page Views, Unique Users, Avg Visits/Person, Top Playbook, Views by
Playbook chart, Views by Region chart, a monthly trend, a "Who's Active" per-person drilldown, and
a "Playbook Intelligence" section (static, hand-written UX recommendations per playbook — not
computed from the traffic data itself).

**Custom formulas:**
- Month bucketing is computed **per row** from that row's own `Date` field, not from the source
  filename — necessary once weekly files started straddling calendar-month boundaries.
- Date-range filters (30D/60D/90D/120D/All) anchor to the **newest date actually present in the
  loaded data**, not to today's real-world date — so the default view auto-advances every time a
  new file drops, with zero code changes needed.

**TLG:** toggle-able "Hide TLG" button, defaults to hidden.

## 3. Internal Dashboard Traffic *(hidden)*

**File / Script:** `dashboard-traffic.html` / `update_dashboard_traffic.py`

**Purpose:** meta-analytics — tracks usage of **our own analytics dashboards** (this whole suite),
answering "who on the team is actually using these tools, and which ones." Deliberately hidden:
no homepage card, reachable only by triple-clicking the homepage's title.

**Data source:** the exact same weekly/monthly Excel pipeline as Playbook Traffic, filtered to rows
whose URL starts with `/learning-development-dashboards/`.

**What it measures:** Total Page Views, Unique Users, Avg Visits/Person, Top Dashboard, "Dashboards
Active" (out of the total dashboard count), Views by Dashboard chart, Views by Region chart, a
trend line (top 5 dashboards by volume), Who's Active drilldown.

**Custom formulas:**
- `DASHBOARD_MAP` translates a URL's filename into the same clean display name used on the
  homepage cards (`generate_homepage.py`) — kept in sync **by hand**, there's no single shared
  source of truth between the two files, so a dashboard rename anywhere needs both updated.
- `DASHBOARD_COLORS` gives each dashboard a consistent chart color (also hand-maintained,
  same risk).
- **As of 2026-09-25, the "All Dashboards" filter dropdown and the Views by Dashboard chart draw
  from the exact same universe on purpose** (`Object.keys(DASHBOARD_COLORS) ∪ every dashboard name
  that appears anywhere in the data`) — there used to be a deliberate exclusion hiding "Analytics
  Hub" and "Playbook Traffic" from the dropdown only, which was removed because the two lists not
  matching was confusing. Don't reintroduce a dropdown-only exclusion here.

**TLG:** toggle-able "Hide TLG" button, defaults to hidden (30-day default view + TLG hidden means
this dashboard's own traffic — visited almost exclusively by TLG people — often reads as very low
activity by default; switch to "All" time + Show TLG to see the full picture).

## 4. Healthcare Certification

**File / Script:** `cert-healthcare.html` / `update_cert_dashboard.py` (`generate_html_healthcare_v2`)

**Purpose:** tracks Healthcare-vertical reps' progress through the Healthcare LMS certification
curriculum — who's certified, who's at risk of missing a deadline, and how reps compare to
managers.

**Data source:** monthly `Healthcare-Certification-Report-*.xlsx` +
`Healthcare-Certification-Foundations-Curricula-Report-*.xlsx`. Accumulated across every monthly
file ever dropped (not latest-file-only) — deduplicated by email, latest file wins per person.

**What it measures:** Total Enrolled, Not Started, In Progress, Completion Rate, Certified (stat
cards); Healthcare Team Progress Update (Reps vs. Managers, grouped bar, % of each group in
Awaiting-Video / ≥50% / <50% tiers); Learners by Market; a Timeline donut
(Certified/On Track/Due Soon/Overdue); Certifications Over Time (Reps vs. Managers, stacked bar by
fiscal quarter); a full certification roster with per-person drill-down.

**Custom formulas:**
- **`isManager(p)`:** job title contains "director of sales", "vice president", or "regional
  account executive" → Manager; everyone else → Rep. Drives the Role filter and every Reps-vs-
  Managers chart on this dashboard.
- **New Hire:** a rolling 65-day window from hire date, checked against the report's own data date
  each regeneration (not a fixed calendar cutoff) — self-maintains with zero manual updates.
- **Due date / deadline:** the LMS's own "Item Required Date" per curriculum if present; otherwise
  a self-computing fallback (the single most common real required-date value across the whole
  current roster) if the person is "In Progress" and not a New Hire; otherwise "Unknown." Status:
  **Overdue** (past due date) / **Due Soon** (≤10 days left) / **On Track** (>10 days left).
- **Completion Rate** is measured as actual 100%-of-coursework completion, **not** the official
  "Certified" flag — the two can diverge (coursework finished but sign-off still pending), and this
  dashboard deliberately surfaces that gap rather than hiding it.
- **Roster tier stripe:** Blue = Certified + all secondary curricula complete; Green = Certified,
  some secondary still open; Amber = LMS-complete but not yet officially Certified; none = still in
  progress.

**TLG:** real Hide/Show toggle (not silent — the button visibly changes state).

**Nav:** bi-directional hamburger menu linking to Playbook Traffic, Public Sector Certification,
Accelerate Onboarding.

## 5. Public Sector Certification

**File / Script:** `cert-publicsector.html` / `update_cert_dashboard.py` (publicsector generator)

**Purpose:** same idea as Healthcare, for the Public Sector vertical — but note the terminology is
deliberately different: PS has no formal "certification," only **completion**. Never call it
"Certified"/"Certification" on this dashboard.

**Data source:** latest-file-only (unlike Healthcare, PS does **not** accumulate across months —
each file is a full active-roster snapshot, so people who've left the vertical drop off naturally
rather than lingering). One row per curriculum item per person.

**What it measures:** Total Enrolled, status pills (Not Started/In Progress/Completed), a
Completion Pipeline chart (3-stage percentage bar), a Learners by Market chart, a card-based roster
with per-person curriculum checklists.

**Custom formulas:**
- Completion date = the **max Item Completion Date** across a person's 3 curriculum items — there
  is no dedicated "curriculum completion date" field in this export format.
- Only 3 curriculum items exist in PS, ever: "Introduction to Public Sector," "Disrupting the
  Public Sector Buying Cycle," "Public Sector Prospecting Research Guide."

**TLG:** real Hide/Show toggle, same as Healthcare.

**Nav:** bi-directional hamburger menu linking to Playbook Traffic, Healthcare Certification,
Accelerate Onboarding.

## 6. Layered Security Certification

**File / Script:** `cert-layered-security.html` / `update_layered_security_dashboard.py`

**Purpose:** tracks completion of the 12-module Layered Security curriculum (a single,
cross-vertical certification, internal code `LSFDS`) and ties it directly to real Closed Won sales
revenue — the only cert dashboard that also tracks a sales outcome, not just training completion.

**Data source:** a 3-file monthly cadence (old dated files get **deleted** each cycle, not
accumulated): a Curricula Report (per-item completion, same schema every month), a Certification
Report (scoped to only already-certified people — presence in this file is itself the "certified"
signal, a hard rule, not a guess), and an OPS FY26 Salesforce export (Closed Won deals ≥ $5,000).

**Exclusions:** Solutions Consultants, Commercial Print market, and TLG are all excluded from the
roster entirely (not just hidden — they're not counted as part of the population at all).

**What it measures:** percent-based Curriculum Complete / In Progress / Not Started stat cards, a
roster table (Learner · Manager · Layered Security % · Overall % · Closed Won).

**Custom formulas:**
- **`Complete`** is derived from **actual module count**, never trusted from the LMS's own
  "Curriculum Complete" flag — that flag can go stale (stuck reporting complete under an old
  11-module requirement even after a 12th module was added).
- **Closed Won:** a deal counts only if Stage = "Closed Won" **and** Amount ≥ $5,000, joined to the
  roster by "Opportunity Owner Email." A Closed Won deal does **not** by itself mark someone
  Certified — Certified comes exclusively from the separate Certification Report file.

**Nav:** triple-click home only (no hamburger menu to/from other dashboards).

## 7. Accelerate Onboarding

**File / Script:** `onboarding.html` / `update_onboarding_dashboard.py`

**Purpose:** tracks new sales reps in the "Accelerate" onboarding cohort through a structured
**35-day** curriculum, joined with their real Salesforce sales performance — answers "is onboarding
actually producing productive reps, and how fast."

**Data source:** monthly LMS curriculum export joined by email with a Salesforce Closed Won
opportunities export.

**What it measures:** per-learner Actual % / Expected % / Gap / Progress / Curricula heatmap / Days
to Close, an "Expected Focus" and "Biggest Gap" column per learner, program-wide stat cards
including average Days to First Sale.

**Custom formulas (the most pacing-driven dashboard in the suite):**
- **Overall %** is **weighted**: total items done ÷ total items across ALL curricula — deliberately
  not a simple average of each curriculum's own percentage, which would over-weight small
  curricula.
- **Pacing schedule:** each curriculum has a prescribed program-day range it's expected to be
  finished within — Getting Started / Sales Workflow / Core Portfolio: days 1-7; Prospecting: days
  1-14; Sales Skills: days 8-21; Pipeline Management: days 22-35. "Expected Focus" and "Biggest Gap"
  are both derived from this schedule.
- **Overdue status** is per-curriculum, using the LMS's own "Item Required Date" where the LMS
  provides one, falling back to a `35 − days elapsed` window when it doesn't. "Coming Soon" courses
  count toward completion totals but can **never** trigger Overdue, regardless of any date.
- **Days to Close** = hire date → the rep's earliest Closed Won deal's close date (deliberately not
  Salesforce's own "Age" field, which measures from opportunity-created-date instead of hire date —
  a truer onboarding-speed metric for this specific cohort).
- **Canadian learners** run a parallel curriculum set (`_BCA`-suffixed IDs) with 3 different courses
  swapped in (CASL, TRUEBLUE, KMPriceHUB+FINTRAC replace 3 US-only courses); everything else is
  identical.
- **Group/Test-Group filter** uses a hardcoded name list, **not** a date field — the LMS resets the
  program-start date on every data pull, so a date-based filter would silently break.

**TLG:** always hidden — no toggle button exists on this dashboard (a deliberate, permanent
exclusion, unlike the toggle-able pattern elsewhere).

**Nav:** bi-directional hamburger menu linking to Playbook Traffic, Healthcare Certification,
Public Sector Certification.

## 8. Accelerate Leaderboard

**File / Script:** `leaderboard.html` / `update_leaderboard_dashboard.py`

**Purpose:** a recognition/incentive tool — ranks Accelerate cohort reps who closed **real
revenue** within their first 45 days on the program. Distinct from Onboarding (#7), which tracks
curriculum *progress*; this tracks *sales outcomes* against a strict eligibility window.

**Data source:** 3 files — the LMS curriculum export, a Salesforce Closed Won export, and a
Salesforce Stage History export.

**What it measures:** 6 stat cards, a market chart, the main ranked Leaderboard table, an "On Deck"
section (in-window reps with a deal that doesn't yet qualify, plus exactly what's missing), a
Program Window Tracker (active vs. expired reps), and Cohort History.

**Custom formulas (this dashboard is almost entirely eligibility logic):** a deal only counts
toward the leaderboard if **all four** are true:
1. It closed within the rep's first **45 days** on the program (`assignToCloseDays ≤ 45`, anchored
   to `assignDate` = program start date — **not** hire date; this cohort was hired months before
   the program itself launched, so the two dates diverge significantly).
2. The rep is **still** within their own 45-day window as of *today* — reps automatically roll off
   the live leaderboard the moment their window expires, even though a deal that qualified while
   they were still in-window stays in the historical record.
3. Curriculum is fully complete (`curriculumComplete = Yes`) — this is a multi-step final state
   (courses done → workshops attended → Boot Camp → a capstone presentation with sign-off), **not**
   simply finishing individual courses.
4. The rep personally moved the deal through **both** the Sales Qualified and Engage stages
   themselves — an inherited or reassigned deal doesn't count.

**"Hide Test Group"** filters the original 27-person June 4 launch cohort, using a hardcoded name
list (same reasoning as Onboarding's Group filter — `assignDate` resets on every LMS pull, so it
can't be used to identify this group reliably).

**Also exports** `leaderboard-data.json`, consumed by the separate Accelerate Sales Playbook
website's homepage to recompute its own live leaderboard section client-side.

## 10. LMS Engagement

**File / Script:** `lms-engagement.html` / `update_lms_engagement_dashboard.py` (built 2026-09-24/25;
originally shipped as "Course Completions")

**Homepage card:** hidden by default as of 2026-09-28 — see the 🔒 note above the index table.

**Purpose:** the **official, audit-matching** org-wide learning-completion report — reproduces the
published FY2025 L&D Learning Completion report exactly (same category/department breakdown, same
BUS/BCA split), with real fiscal-year year-over-year comparisons. The rigorous counterpart to
LinkedIn Learning Engagement (#9)'s more exploratory framing — this is the one to trust for
official reporting.

**Data source:** a real monthly Course Completions LMS export, plus a LinkedIn Learning export
(currently only a one-time historical baseline is available, extracted from a prototype file — a
fresh monthly LinkedIn export hasn't been supplied yet; drop one in `lms-engagement-data/` the
same way as the LMS file whenever one arrives, no code changes needed).

**Architecturally unique in this repo:** rather than reimplementing Resmie's classification rules
in Python, a Node pipeline runs her own delivered JavaScript **verbatim** against the raw source
files, so her business logic can never silently drift from what she actually specified. Python only
takes over once the data is ready, to apply house styling and write the final HTML.

**What it measures:** a Learning Completion Summary matching the published report's exact
breakdown, "Your Filtered View" year-over-year, three separate YoY comparison tables (All Learning
/ Without Compliance / BUS vs BCA Without Compliance), a Top 20 Courses by hours table, and a
stacked monthly bar chart.

**Custom formulas (the most formula-dense dashboard in the suite):**
- **Compliance detection:** a course counts as Compliance if it's on a hardcoded 62-course-ID list
  from the published report, **or** it auto-matches a rule (course ID/title contains a year "20xx"
  **and** the title contains a compliance-type phrase — "Code of Conduct," "Phishing," "HIPAA,"
  "FCPA," etc.). LinkedIn courses are never auto-flagged as compliance. Either detection can be
  manually overridden per-course in the dashboard's own "Course rules" panel.
- **Instructor-Led department** is assigned in priority order: a manual override → the real
  department recorded for that course ID in the published FY2025 report → an ID-prefix fallback
  (GCS/SERVICENXT → Global Client Services; MMS → Corporate; T → Technical Training; anything
  else → Sales Training).
- **LinkedIn precedence:** for any month a real LinkedIn Learning export covers, LinkedIn hours use
  that export's actual hours-viewed; for months without one, LinkedIn completions logged in the LMS
  file count at a default course length (30 minutes, adjustable in Calculation Rules).
- **BCA detection:** user ID starts with "C" followed by a digit, **or** email ends in `.ca` /
  `@itweapons.com`.
- **Course length:** the LMS export's own hours field; a blank length defaults to 30 minutes
  (adjustable).
- **Published-report reconciliation:** calculated FY2025 figures intentionally run lower than the
  published report, because people who've since left the company still appear in the published
  report's historical snapshot but no longer appear in the current LMS export. This is expected,
  documented behavior, not a bug — always compare FY2025 vs. FY2026 using the *calculated* rows so
  both years are counted the same way.

**TLG:** **no toggle exists at all** — the data model deliberately never stores names or emails,
only anonymized IDs, so excluding TLG is structurally impossible here, not merely unmapped like
dashboard #9.

**Export:** a real Export ▾ dropdown — PDF prints the on-screen report exactly as filtered; Excel
writes a 7-sheet workbook (Summary, Monthly, Your Filtered View YoY, Learning Completion Summary,
YoY All/No-Compliance, Top Courses), all computed from the same live numbers shown on screen.
